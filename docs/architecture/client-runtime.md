# Client runtime and service mapping

Date: 2026-10-24

The core package creates AWS SDK service clients configured for LocalStack. The [glossary](../../GLOSSARY.md) distinguishes an AWS service, an SDK client, and a configured LocalStack endpoint.

## Endpoint catalog

[`AwsServiceEndpointMetadata.All`](../../src/LocalStack.Client/Enums/AwsServiceEndpointMetadata.cs) is the catalog of service IDs, CLI names, catalog keys, and historical per-service ports. [`Config`](../../src/LocalStack.Client/Config.cs) derives an endpoint from that catalog and `ConfigOptions`: a host, HTTP or HTTPS scheme, and either the shared edge port (the default) or a legacy service port. The service ID lookup is an exact match against the AWS SDK's metadata value; a CLI name or enum spelling is not interchangeable with it. Ports are not unique service identifiers.

The catalog is a mapping in **this library**, not a list of all AWS operations available in LocalStack. LocalStack's own service, edition, release, and operation coverage determines emulator capability. The official [LocalStack Python client](https://github.com/localstack/localstack-python-client) is an input when this catalog gains services, but a Python mapping is not itself proof of emulator behavior or of a mapping in this .NET release. A particular .NET release can create a LocalStack-configured client through `Session` for a service only after its own catalog contains the service ID. Until then, `Session` throws `NotSupportedClientException` for the missing mapping; that exception does **not** mean the emulator lacks the service. Functional-test counts do not define product support. Claims about an exact operation on a named LocalStack image or edition need separate evidence.

## Client creation

[`Session`](../../src/LocalStack.Client/Session.cs) retains its three-argument constructor accepting `ISessionOptions`, `IConfig`, and an injected `ISessionReflection`. On `net10.0`/`net11.0`, `CreateClientByInterface<TClient>()` uses AWS SDK v4 static factories when the helper is exactly the default [`SessionReflection`](../../src/LocalStack.Client/Utils/SessionReflection.cs): `TClient.CreateDefaultClientConfig()` supplies the config and its `ServiceId` identifies the endpoint; `TClient.CreateDefaultServiceClient(...)` creates the client with the configured credentials. This path needs no source generation and also works in F#/VB. A custom or mocked helper retains the previous helper calls and ordering. The `Type` interface path locates the implementation by convention; both implementation overloads start from a concrete type and use the helper.

The client configuration sets `UseHttp`, `ProxyHost`, and `ProxyPort` from the LocalStack settings. The modern generic interface path sets S3 `ForcePathStyle` through a [string-named `UnsafeAccessor`](../../src/LocalStack.Client/Utils/S3ForcePathStyle.cs); helper paths use that accessor, a generated setter, or the JIT reflection fallback where applicable. With `useServiceUrl: true`, `Session` sets the explicit `ServiceURL`; otherwise it requires a region name and sets `RegionEndpoint`. These are two configuration paths for a LocalStack-created client, **not** the application-level LocalStack/AWS mode switch. They do not by themselves prove where every later request travels.

For the modern `Type` APIs and default helper, the [slim generator](../../src/LocalStack.Client.Generators/AwsRegistryGenerator.cs) discovers source class declarations with bases and public types in references that contain or directly reference the AWS client base assembly. It excludes generic, file-local, and inaccessible types; eligible clients are concrete, with supported constructors/configs. It emits direct C# operations: `UnsafeAccessor` for `serviceMetadata`, `new TConfig()`, direct client constructors, a setter for the simple public bool `ForcePathStyle` shape, and a plain-`RegionEndpoint` flag. Constructor and property eligibility rules stay in the generator. The registry keys by runtime type identity and stores delegates; operations remain lazy at their helper/session call sites, including on JIT.

Registry misses and unusual shapes use the previous reflection code only while [`ReflectionFallback.IsSupported`](../../src/LocalStack.Client/Utils/ReflectionFallback.cs) is true. Its feature guard removes that fallback under trimming/Native AOT; the [platform boundary](platform-and-packaging.md#native-aot-and-trimming) lists miss behavior and compiler/type limits. The `netstandard2.0`/`net472` assets keep their previous reflection paths.

[`SessionStandalone`](../../src/LocalStack.Client/SessionStandalone.cs) creates this session without dependency injection. The optional Extensions package owns the application-level mode switch in [Extensions and composition](extensions-and-composition.md). See [platform and packaging](platform-and-packaging.md#native-aot-and-trimming) for the 3.0.0 Native AOT qualification lane and compiler-asset packaging.
