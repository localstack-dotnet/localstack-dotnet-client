# Native AOT support preserves existing consumer code

Native AOT support for this library means that an application using the existing public entry points publishes and runs under strict trimming and Native AOT without changing those calls. Examples of such entry points are `services.AddLocalStack(configuration)` with `services.AddAwsService<IAmazonS3>()`, or a Core `Session`. Configuration, lifetime, injection, and exception behavior must stay intact. A separate AOT-only registration or factory path that consumers must migrate to does not meet this goal on its own, because it moves the cost to every consumer and leaves the documented entry points unsupported.

An additive opt-in API, such as typed options or an explicit factory, is easier to make trim-safe while the existing calls stay reflection-based. It is not the chosen direction. Techniques that keep the existing calls remain in scope, and no single technique is chosen yet. Two examples are build-time generation, explored in [draft PR #49](https://github.com/localstack-dotnet/localstack-dotnet-client/pull/49), and the SDK's public factories.

If a change to consumer code or the public API proves unavoidable, the maintainer must decide it before implementation starts. The proposal names the exact consumer call that has to change and why. Acceptance evidence is an unchanged consumer of the existing calls, built with strict trimming and Native AOT and executed, not a new consumer of a new path. The [platform boundary](../architecture/platform-and-packaging.md#native-aot-and-trimming) owns the current support status.
