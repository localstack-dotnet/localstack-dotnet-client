# Extensions and application composition

Date: 2026-10-23

`LocalStack.Client.Extensions` integrates the core package with .NET configuration and dependency injection. The [client runtime](client-runtime.md) owns endpoint mapping and LocalStack client creation; this document owns application-level composition.

[`AddLocalStack(IConfiguration)`](../../src/LocalStack.Client.Extensions/ServiceCollectionExtensions.cs) binds the `LocalStack` section to `LocalStackOptions`, `SessionOptions`, and `ConfigOptions`. The unreleased implementation uses [fixed-schema typed mutation](../../src/LocalStack.Client.Extensions/LocalStackOptionsBinder.cs), not general reflective configuration binding. Private setters and defaults are retained. Binding stays lazy inside the existing three `Configure` registrations, preserving conversion behavior and the framework's configure/post-configure, validation, and caching pipeline. The aggregate's nested session/configuration objects and the separately registered options remain independent instances.

It registers `IConfig` as transient and `ISessionReflection`, `ISession`, and `IAwsClientFactoryWrapper` as singletons. Registration prepares both client-creation paths; it does not itself enable LocalStack mode. On `net10.0`/`net11.0`, every Add/TryAdd/alias overload uses the generic interface session path in LocalStack mode: with exactly the default `SessionReflection`, AWS SDK v4 static factories create the config/client without runtime reflection or source generation, including in F#/VB. Custom or mocked helpers retain the previous calls and ordering. Core's slim generator serves the `Type` APIs automatically in net10-compatible C# package consumers, including Extensions-only references. The [platform boundary](platform-and-packaging.md#native-aot-and-trimming) owns the unreleased 3.0.0 scope and JIT-only fallback limits.

`AddAwsService<TService>` registers an AWS service interface (singleton by default). When the configured `UseLocalStack` value is `true`, resolution calls `Session.CreateClientByInterface<TService>` and uses the LocalStack catalog. When it is `false`—the options default—resolution calls [`AwsClientFactoryWrapper`](../../src/LocalStack.Client.Extensions/AwsClientFactoryWrapper.cs) to create an ordinary AWS SDK client. `AddAWSServiceLocalStack<TService>` is an alias for the registration method, **not** an override of the mode switch. `TryAddAwsService<TService>` only adds a registration when one is absent.

The AWS-mode wrapper obtains the client factory from the SDK's public `AddAWSService<TService>` registration and invokes it with the original `IServiceProvider`. This preserves SDK options fallback and logger access without reflecting over private SDK members or constructing a second provider. Explicit options still override provider defaults, the outer registration owns the client lifetime, and factory exceptions retain the `TargetInvocationException` boundary. The public wrapper and interface remain available. The [decision record](../adr/0002-aws-setup-constructor-compatibility.md) explains the provider-aware public factory choice.

Both `TryAddAwsService<TService>` overloads forward `useServiceUrl`, including the shorter `(lifetime, useServiceUrl)` overload fixed for #63; the switch selects a client configuration path after LocalStack mode is chosen and is distinct from `UseLocalStack`.
